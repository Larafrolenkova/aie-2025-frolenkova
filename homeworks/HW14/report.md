# HW14 – эмбеддинги, FAISS, оценка retrieval и mini-RAG по базе знаний

## 1. Кратко: что сделано

- В качестве базы знаний использовалось подмножество датасета SQuAD v1.1. Он был выбран, потому что содержит текстовые фрагменты из Wikipedia, а также готовые вопросы и ответы, что удобно для проверки retrieval.
- Документы были разбиты на текстовые фрагменты с помощью простого чанкинга. Основной вариант использовал `chunk_size = 300` и `overlap = 50`, так как он показал лучшие результаты в эксперименте.
- Для построения векторных представлений использовался `TfidfVectorizer`. Полученные векторы были добавлены в индекс `FAISS` для поиска ближайших фрагментов.
- Базовая проверка retrieval показала, что качество поиска зависит от согласованности запросов с базой знаний. При использовании вопросов из выбранного подмножества SQuAD система находила релевантные фрагменты.
- После обновления базы знаний были добавлены новые документы об Альберте Эйнштейне, Николе Тесле и ДНК. Для соответствующих запросов результаты поиска улучшились: новые документы стали попадать в top-k выдачу.
- Mini-RAG был реализован как простой конвейер: запрос пользователя → поиск top-k фрагментов → сбор контекста → формирование ответа → вывод источников. Система корректно работает на конкретных вопросах, но хуже справляется с общими или неоднозначными запросами.

- Python:  3.13.1

## 3. База знаний и подготовка документов

- предметная область: энциклопедические тексты общего характера (различные темы из Wikipedia).
- источник документов: подмножество датасета SQuAD v1.1.
- число исходных документов: 877.
- число чанков после разбиения: 2143.
- какой способ чанкинга использовался: простой посимвольный чанкинг с перекрытием.
- основные параметры чанкинга: chunk_size = 300, overlap = 50.
- комментарий (3-6 предложений): выбранная база знаний содержит связные текстовые фрагменты, в которых ответы на вопросы явно присутствуют в контексте. Это важно для задач retrieval, так как позволяет корректно оценивать, найден ли релевантный фрагмент. Использование SQuAD даёт готовые пары «вопрос–ответ», что упрощает проверку качества поиска. При этом тексты достаточно разнообразны, что делает задачу retrieval нетривиальной. Такая структура данных хорошо подходит для построения mini-RAG, поскольку найденные чанки можно напрямую использовать как контекст для формирования ответа.

## 4. Retrieval и индекс

### 4.1. Эмбеддинги и индекс

- какая embedding-модель или способ векторизации использовались:
  Использовался `TfidfVectorizer` из библиотеки `sklearn` для преобразования текстовых фрагментов в векторы фиксированной размерности.
- какая метрика сходства использовалась:
  Использовалось евклидово расстояние (L2 distance), реализованное в FAISS.
- какой индекс `FAISS` использовался:
  Использовался индекс `IndexFlatL2`, обеспечивающий точный поиск ближайших векторов.
- какой `top_k` использовался по умолчанию:
  По умолчанию использовалось значение `top_k = 3` (для примеров) и `top_k = 5` (для оценки качества).
- что показали первые примеры retrieval:
  Первоначально при использовании произвольных запросов результаты были нерелевантными, так как запросы не соответствовали содержимому базы знаний. После перехода к запросам из того же подмножества SQuAD retrieval стал возвращать релевантные фрагменты, содержащие правильный ответ или связанный с ним контекст.

### 4.2. Контрольные запросы и оценка retrieval

- Сколько контрольных запросов использовалось:
  Использовалось 10 контрольных запросов.
- Что считалось релевантным ответом:
  Релевантным считался чанк, содержащий ожидаемый ответ (строку из SQuAD), либо чанк из ожидаемого документа (по заголовку статьи).
- Какие метрики retrieval считались:
  Рассчитывались метрики `hit@k` и `recall@k`.
- Итоговый `hit@k`:
  hit@1 = 0.6, hit@3 = 0.6, hit@5 = 0.8 (для выбранного chunk_size = 300).
- Итоговый `recall@k`:
  recall@1 = 0.6, recall@3 = 0.6, recall@5 = 0.8.
- Дополнительные метрики (если были):
  Рассчитывалась метрика `MRR`, значение составило 1.0.
- Какие запросы оказались самыми простыми:
  Запросы, для которых в базе знаний присутствовал явный и короткий ответ (например, вопросы о конкретных фактах — имя человека, место или определение).
- Какие запросы оказались самыми проблемными:
  Более общие или неоднозначные запросы, а также вопросы, требующие более широкого контекста или отсутствующие в базе знаний до её обновления.
