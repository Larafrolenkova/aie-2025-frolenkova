## 2. Структура проекта

Проект организован в следующей структуре:

- `requirements.txt` — список библиотек Python, необходимых для установки и запуска проекта;
- `README.md` — инструкция по установке, обучению модели, запуску сервиса и тестированию;
- `report.md` — отчёт по проекту, содержащий постановку задачи, описание данных, результаты экспериментов и архитектуру решения;
- `self-checklist.md` — чек-лист самопроверки проекта перед сдачей;
- `notebooks/` — экспериментальные ноутбуки:
  - `exp01_eda.ipynb` — разведочный анализ данных;
  - `exp02_baseline_models.ipynb` — обучение и оценка базовых моделей;
  - `exp03_model_comparison.ipynb` — сравнение улучшенных моделей;
  - `original_course_notebook.ipynb` — исходный экспериментальный блокнот;
- `src/` — основной программный код проекта:
  - `config.py` — загрузка настроек проекта;
  - `data.py` — загрузка и подготовка данных;
  - `features.py` — формирование временных и пространственных признаков;
  - `train.py` — обучение, сравнение и сохранение моделей;
  - `predict.py` — загрузка сохранённой модели и получение прогноза;
  - `schemas.py` — описание входных и выходных данных API;
  - `service.py` — запуск сервиса прогнозирования;
- `data/` — данные проекта:
  - `raw/train.csv` — полный обучающий набор данных;
  - `sample/test.csv` — небольшая демонстрационная выборка;
  - `README.md` — описание источника данных и ожидаемой структуры файлов;
- `configs/` — конфигурационные файлы:
  - `config.yaml` — пути, параметры обучения и настройки сервиса;
  - `.env.example` — пример переменных окружения;
- `tests/` — автоматические проверки:
  - тест формирования признаков;
  - тест загрузки и использования модели;
  - тест эндпоинта `/health`;
- `artifacts/` — результаты работы проекта:
  - `taxi_duration_pipeline.joblib` — сохранённая модель вместе с предобработкой;
  - `model_metrics.json` — метрики финальной модели;
  - `experiment_results.csv` — результаты сравнения моделей.

Полный обучающий файл `train.csv` не рекомендуется хранить в публичном репозитории из-за его большого объёма. Перед запуском проекта его необходимо самостоятельно поместить в каталог `data/raw/`.

## 3. Требования и установка

### 3.1. Требования

Для запуска проекта необходимы:

- Python версии 3.10 или выше;
- установленный менеджер пакетов `pip`;
- обучающий файл `train.csv`, размещённый в `data/raw/`;
- доступ к командной строке или терминалу.

Дополнительные системные зависимости и внешние сервисы для локального запуска не требуются. Docker не является обязательным.

### 3.2. Установка окружения

Сначала необходимо перейти в каталог проекта:

```bash
# Перейти в папку проекта
cd project

# Создать виртуальное окружение (опционально, но рекомендуется)
python -m venv .venv

# Активировать окружение:
# Linux / macOS:
source .venv/bin/activate

# Установить зависимости
pip install --upgrade pip
pip install -r requirements.txt
```

Если у проекта есть какие-то особенности установки (дополнительные шаги, внешние сервисы и т.п.), опишите их здесь.

## 4. Как запустить проект

### 4.1. Запуск экспериментальных ноутбуков

Для запуска Jupyter Notebook необходимо выполнить команду:

bash jupyter notebook 

После запуска в браузере откроется интерфейс Jupyter Notebook. Экспериментальные ноутбуки находятся в каталоге notebooks/.

Рекомендуемый порядок работы:

1. notebooks/exp01_eda.ipynb — разведочный анализ данных;
2. notebooks/exp02_baseline_models.ipynb — построение и оценка базовых моделей;
3. notebooks/exp03_model_comparison.ipynb — сравнение улучшенных моделей.

Ноутбуки предназначены для анализа данных, построения графиков, проверки гипотез и сравнения качества моделей.

Перед запуском ноутбуков необходимо убедиться, что файл обучающего набора данных расположен по пути:

text data/raw/train.csv 

### 4.2. Запуск обучения модели

Перед обучением модели необходимо активировать виртуальное окружение и перейти в корневой каталог проекта.

Полное обучение на всём наборе данных запускается командой:

bash python -m src.train 

Поскольку файл train.csv содержит более 1,4 млн записей, для быстрой проверки можно ограничить количество используемых строк:

bash python -m src.train --max-rows 200000 

После завершения обучения в каталоге artifacts/ будут созданы следующие файлы:

text artifacts/taxi_duration_pipeline.joblib artifacts/model_metrics.json artifacts/experiment_results.csv 

Назначение файлов:

- taxi_duration_pipeline.joblib — сохранённая модель вместе с этапами предобработки;
- model_metrics.json — метрики выбранной модели;
- experiment_results.csv — результаты сравнения всех моделей.

### 4.3. Запуск сервиса

После обучения модели сервис можно запустить командой:

bash python -m src.service 

Также доступен запуск через Uvicorn:

bash uvicorn src.service:app --host 127.0.0.1 --port 8000 

Сервис запускается локально на порту 8000.

Документация Swagger UI доступна по адресу:

text http://127.0.0.1:8000/docs 

В сервисе реализованы два основных эндпоинта:

- GET /health — проверка работоспособности сервиса и наличия загруженной модели;
- POST /predict — получение прогноза продолжительности поездки.

Проверить работу эндпоинта /health можно в браузере:

text http://127.0.0.1:8000/health 

Или с помощью команды:

bash curl http://127.0.0.1:8000/health 

Пример ответа:

{
  "status": "ok",
  "model_loaded": true,
  "model_version": "1.0.0"
}
Пример запроса к эндпоинту /predict:

curl -X POST http://127.0.0.1:8000/predict \
  -H "Content-Type: application/json" \
  -d '{
    "vendor_id": 1,
    "pickup_datetime": "2016-06-18T18:30:00",
    "passenger_count": 2,
    "pickup_longitude": -73.9855,
    "pickup_latitude": 40.7580,
    "dropoff_longitude": -73.9730,
    "dropoff_latitude": 40.7648,
    "store_and_fwd_flag": "N"
  }'

Пример ответа сервиса:

{
  "predicted_duration_seconds": 742.15,
  "predicted_duration_minutes": 12.37,
  "model_version": "1.0.0"
}

Для остановки сервиса необходимо нажать сочетание клавиш:

text Ctrl + C

## 5. Данные

Для обучения используется открытый набор данных New York City Taxi Trip Duration, опубликованный на платформе Kaggle.

Источник данных:

text https://www.kaggle.com/competitions/nyc-taxi-trip-duration/data 

Обучающий файл содержит сведения о завершённых поездках, включая:

- идентификатор поставщика;
- дату и время начала поездки;
- дату и время окончания поездки;
- количество пассажиров;
- координаты точки посадки;
- координаты точки высадки;
- признак сохранения и последующей передачи данных;
- продолжительность поездки trip_duration.

Файлы проекта размещаются в следующей структуре:

data/
├── raw/
│   └── train.csv
└── sample/
    └── test.csv

Файл data/raw/train.csv используется для обучения и оценки моделей. Он должен содержать целевую переменную trip_duration.

Файл data/sample/test.csv предназначен для демонстрационных запусков, проверки формирования признаков и получения прогнозов.

Полный набор данных не рекомендуется добавлять в публичный репозиторий из-за большого объёма. В репозитории следует хранить только небольшую открытую или обезличенную выборку.

## 6. Тесты

В проекте реализованы следующие автоматические проверки:

- test_features.py — проверка формирования временных и пространственных признаков;
- test_predict.py — проверка обработки ситуации, когда файл обученной модели отсутствует;
- test_service.py — проверка работоспособности эндпоинта /health.

Для запуска всех тестов необходимо выполнить:

bash pytest tests 

Для получения подробного вывода:

bash pytest tests -v 

Тесты рекомендуется запускать после установки зависимостей и перед демонстрацией проекта.

## 8. Ограничения и дальнейшая работа

Текущая версия проекта имеет следующие ограничения:

- модель использует исторические данные и не учитывает фактическую дорожную ситуацию;
- не учитываются пробки, перекрытия дорог и дорожно-транспортные происшествия;
- расстояние вычисляется между географическими координатами и не соответствует точной длине маршрута по дорожной сети;
- используются данные за 2016 год;
- сервис не содержит авторизации;
- история запросов не сохраняется;
- отсутствует автоматический мониторинг дрейфа данных;
- обучение на полном наборе данных требует значительного времени и объёма оперативной памяти.

В дальнейшем проект можно развивать в следующих направлениях:

- добавить данные о дорожной загруженности;
- учитывать погодные условия;
- рассчитывать фактическую длину маршрута по дорожному графу;
- применить более современные алгоритмы градиентного бустинга;
- выполнить расширенный подбор гиперпараметров;
- добавить временную кросс-валидацию;
- сохранять историю прогнозов;
- добавить авторизацию;
- реализовать мониторинг качества модели;
- разработать веб-интерфейс;
- настроить автоматическое переобучение модели.
